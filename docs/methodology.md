# Methodology and data interpretation

The experiment retains vehicle IDs, route references or inline edge sequences, child XML elements and planned departure schedules. Inline routes without original IDs retain null route_id; route_edges records their sequence. A seeded permutation places 25 vehicles into each persona; run index rotates persona membership so each vehicle receives every persona exactly once in twelve runs. SHA256-derived independent assignment, sampling and SUMO seeds are in the manifest and tables. Parameter values use uniform sampling and 17-digit XML serialization. Reproducibility assumes the same input hashes, configuration, SUMO build, Python dependencies and invocation. Action steps round upward to simulation-step multiples and must not exceed tau. Each driver has a unique type and explicit vehicle speedFactor; speedDev is zero.

Installed routes XSD validation, SUMO XML validation and actual departure-time getters verify support. startupDelay is accepted by the installed schema and executable, but its generic car-following getter returns an empty string: observed_parameters records null. Other observed values are compared with sampled values. Krauss and LC2013 are fixed. Ballistic integration is explicit to support delayed action steps. No external control changes driving behaviour.

TraCI subscriptions collect the state after each step, including internal lanes. Lane limits come from the actual lane API. Dynamic next-TLS subscription values are observations only; they never establish red-light violations. Leader search uses 200 m minimum lookahead along current best lanes and may return further leaders. Missing leaders, sentinel values and undefined divisions produce nulls. Physical gap = TraCI leader gap + ego minGap, per installed 1.28 Python API and https://sumo.dlr.de/docs/TraCI/Vehicle_Value_Retrieval.html . Time headway = physical gap / ego speed for positive speed. Longitudinal TTC = physical gap / positive closing speed, requiring nonnegative gap. This is distinct from SUMO SSM TTC, DRAC or PET. SSM is optional and not enabled; no SSM table is fabricated.

Jerk is the difference of consecutive acceleration observations divided by elapsed step, null at first observation or after gaps. Telemetry uses a fixed nullable Arrow schema, ZSTD compression, run_id partition folders and 10,000-row writes. Trip speed quantiles are exact sampled quantiles retained per vehicle for the capped run. The first observation, last arrival step and teleport discontinuities are excluded from distance/time exposure. Thus exposed_km is sampled coverage, not authoritative route length. Distance-weighted speed ratio weights consecutive observed distance increments; all speed comparisons are relative to the unverified SUMO lane speed, never legal speeding.

Thresholds are CLI configurable and recorded in manifest.json: acceleration >=3 m/s², braking <=-4.5 m/s², network speed ratio >1.05, physical headway <1 s, closing TTC <1.5 s; minimum qualifying episode duration 1 s. Contiguous steps count as one event. Event start is the preceding sample boundary; peak_value is acceleration, braking magnitude, ratio, inverse headway or inverse TTC respectively. Teleport gaps terminate episodes. Official lanechange XML supplies lane-change events and reasons; edge transitions do not create events. Lane-change edge_id is null; from lane is retained, full source details remain in raw XML. Rates divide by exposed kilometres and are null for zero exposure.

TripInfo is authoritative for departure, arrival, duration, routeLength, waitingTime, timeLoss and departure delay; unfinished output is enabled and negative arrival is null. Every expected driver is left-joined, including those not inserted by the cap. Incomplete includes not-departed vehicles; not_departed_count is separately available. Pending departures cannot be called failures, so failed_departures_count is null. Teleport event counts and distinct teleported drivers come from starting teleport IDs. Collision records come from official XML; colliding_vehicle_step_count is separately labelled. Runs end when minExpectedNumber is zero or at the cap. Raw TripInfo, lane changes, collisions, statistics, SUMO log, warnings, command, generated scenario and actual getter values are preserved for each run.

network_speed_audit.json enumerates all tertiary lanes at approximately 80 km/h and their edge IDs and exact values. network_speed_status remains unverified: no authoritative legal-limit evidence has been supplied. The source network is never rewritten. data_dictionary.json describes each exported field with Arrow type, units, provenance and missingness; actual null counts and Parquet row counts are in data_quality.json. simulation_runs and manifest preserve version, hashes, OS, seeds, thresholds and command options. Data outputs are synthetic observations and contain no classification, scoring, premiums or ML models.

The speed-status CLI accepts unverified, validated and corrected. The latter two require an existing --speed-limit-evidence provenance file; this is a recorded caller declaration and does not independently certify legal limits or rewrite the network. All executed runs use unverified. Telemetry physical Parquet files omit run_id because it is encoded in the Hive partition path; the logical dataset and dictionary include it. See docs/experiment_report.md for actual execution results and missing data.
